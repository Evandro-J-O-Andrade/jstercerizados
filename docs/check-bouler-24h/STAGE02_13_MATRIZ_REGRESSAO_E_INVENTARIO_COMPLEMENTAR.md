## Governança e limites (obrigatórios)

- **Somente leitura/documentação.** Sem migrations aplicadas, DDL/DML remoto, `GRANT/REVOKE`, alterações em RLS/policies/functions/views, Storage/buckets/policies/data moves, Edge deploy/config, código funcional, commit, push ou deploy **sem autorização específica por fase**.
- `adm.txt` permanece fora do escopo/versionamento salvo decisão explícita.
- Cada achado é rotulado: **OBSERVADO** (evidência local/remota citada em 02.x), **REPORTADO** (informado pelo operador/auditoria remota desta rodada, não reconsultado nesta execução), **PENDENTE** (exige consulta/prova), **PROPOSTO** (ação futura não autorizada).
- **Não reduzir privilégios nem alterar semântica** de `is_tenant_member`/`user_has_permission`/helpers RBAC sem mapa completo de dependências + testes de regressão aprovados.

## Cadeia de autorização obrigatória (teste e correção)

`auth.users` → `people` (`people.auth_user_id = auth.users.id`) → `tenant_memberships` → `role_assignments` → `roles` → `role_permissions` → `permissions` (`resource.action`) → `PlatformUserContext` (sistema/tenant/unidade/cidade validados no servidor) → `DispatcherMaster` → dispatcher da célula → RLS/Storage/função/Edge + **auditoria registrada**.

Regras: frontend/contexto não é prova; membership ativa ≠ permissão; menu visível ≠ autorização; negar por padrão; tenant/unidade/cidade/sistema/recurso validados server-side; acesso direto (URL, UUID, RPC, Storage API, `tenant_id` adulterado) deve ser negado quando fora do escopo.

## 02.13.4 — Critérios globais de aprovação (antes/depois)

Uma correção só é “aprovada” quando houver, no escopo autorizado:

1. **Evidência antes:** estado remoto/local, policy/grant/contrato, queries/casos afetados.
2. **Teste positivo:** ator autorizado realiza a operação.
3. **Teste negativo:** ator não autorizado é negado (RLS/Storage/Edge/guard).
4. **Isolamento:** tenant A ≠ tenant B; unidade/cidade/sistema quando aplicável.
5. **Acesso direto:** URL/UUID/RPC/Storage API/`tenant_id` adulterado não burlam.
6. **Auditoria:** operação sensível deixa trilha verificável.
7. **Regressão:** amostra da matriz 02.13.1 para domínios dependentes.
8. **Rollback:** script/plano documentado; sem delete de origem em migrações de dados antes de verificação dupla.
