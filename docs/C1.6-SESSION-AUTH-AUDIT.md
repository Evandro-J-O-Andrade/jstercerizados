# C1.6 — Sessão de navegador + Sessões Ativas

## Objetivo

Fechar comportamento de autenticação/sessão e implementar Sessões Ativas usando apenas estrutura real do Supabase.

## Requisito funcional

- F5 mantém a sessão
- reload mantém a sessão
- navegação entre rotas mantém a sessão
- troca de aba mantém a sessão
- aba parada mantém a sessão
- fechar navegador inteiro -> na próxima abertura, login necessário
- logout manual encerra a sessão atual
- Sessões Ativas permite:
  - ver sessão atual
  - ver outras sessões
  - identificar dispositivo/navegador
  - ver data/hora do último acesso
  - encerrar uma sessão individual
  - encerrar todas as outras sessões

## Não é solução aceitável

- logout por inatividade
- logout por timeout
- logout em `beforeunload` como regra principal
- apagar token no `localStorage` para simular “fechou = acabou”
- destruir sessão no F5/refresh/mudança de rota

## Contrato desejado

```
LOGIN
 ↓
sessão Supabase Auth
 ↓
refresh token válido
 ↓
F5 / reload / navegação -> sessão permanece
 ↓
fechar navegador
 ↓
na próxima abertura:
sessão persistida não é suficiente
 -> usuário deve autenticar novamente
```

## Regra técnica

- Não duplicar o mecanismo do Supabase Auth
- Não criar tabela `active_sessions` sem confirmar que `sessions` já não cobre o caso
- A UI de Sessões Ativas deve refletir sessões reais, não estado local
- Encerrar sessão deve invalidar/revogar efetivamente a sessão

## Implementação

### 1. AuthContext

- Manter `supabase.auth.getSession()` e `onAuthStateChange`
- Garantir que `persistSession` do Supabase client permaneça habilitado
- Não adicionar `beforeunload` para logout
- Não adicionar timeout/inatividade automático
- Garantir que `changePassword` continue usando sessão autenticada

### 2. Sessões Ativas

- Usar `sessions` do Supabase Auth como fonte de verdade
- Listar sessões do usuário autenticado
- Permitir revogação de sessão individual
- Permitir revogação de todas as outras sessões
- Registrar eventos em `security_events` ou `audit_logs` quando disponível

### 3. Regras de exibição

- Usuário vê apenas suas próprias sessões
- admin_master pode ver sessões de usuários do tenant conforme RLS
- Mostrar:
  - dispositivo/navegador
  - sistema operacional
  - IP
  - última atividade
  - status (ativa/invalidada)
