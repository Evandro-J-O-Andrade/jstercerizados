# C1.7 — Plano de Reconciliação e Enterprise IA

## Escopo

- Somente sistema de gestão.
- Site público: fora do escopo.
- Sem inventar tabelas, permissões, módulos ou dados.
- Sem implementar dashboard/sidebar definitiva antes de fechar a matrix do banco.

## Frentes

### C1.7-A — Session Lifecycle

- Investigar por que F5/reload encerra sessão.
- Separar: persistência de token, hidratação do AuthContext, encerramento explícito, encerramento ao fechar navegador.
- Não usar `sessionStorage` como autoridade de autenticação.
- Não desligar persistência do Supabase sem resolver o reload.
- Não implementar logout por inatividade/timeout.
- Validar fluxo: login → primeiro acesso → terms → welcome → dashboard.

### C1.7-B — Supabase → Module Matrix

- Levantar todas as tabelas reais do schema canônico.
- Mapear: domínio, PK, UUID, tenant_id, FKs, colunas, tipos, RLS, policies, permissions, operações permitidas.
- Gerar matriz: tabela → módulo → permission → rota → UI.
- Fechar mapeamento de domínios existentes, sem criar domínios fictícios.

### C1.7-C — Enterprise Information Architecture

- Definir header, sidebar, dashboard, módulos, submódulos, rotas, cards, tabelas, filtros, formulários, detalhes, relatórios.
- Somente depois da matrix C1.7-B.
- Tudo baseado em tabelas reais e permissions reais.

## Critério de aceite

- F5 mantém sessão.
- Fechar navegador encerra sessão.
- Fluxo de primeiro acesso funciona sem senha atual.
- Matrix do banco fechada.
- Nenhuma alteração no site público.
