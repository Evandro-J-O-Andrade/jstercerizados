## 3. ACHADO CRÍTICO — o catálogo do registry não renderiza as páginas do catálogo

Este é o resultado mais importante do A8.3 e precisa ser registrado antes de
qualquer reorganização.

Em `src/App.tsx:300-306` e `src/App.tsx:325-331`:

```tsx
{
  module.features && module.features.length > 0 ? (
    React.createElement(createModuleDashboardPage(module.id))
  ) : PAGE_COMPONENTS[MODULE_PAGE_MAP[module.id]] ? (
    React.createElement(PAGE_COMPONENTS[MODULE_PAGE_MAP[module.id]])
  ) : (
    <ComingSoonPage title={module.title} />
  );
}
```

Verificação feita em `PORTAL_MODULES`: **27 de 28 módulos declaram `features`.
O único sem `features` é `inicio`**, e ele é excluído do filtro de rota
(`module.route !== '/dashboard'`).

Consequência: a condição do primeiro ternário é **sempre verdadeira** para todo
módulo roteado. Portanto:

- `PAGE_COMPONENTS` **nunca é consultado** para módulos.
- `MODULE_PAGE_MAP` **nunca é consultado** para módulos.
- `createModuleDashboardPage` renderiza **apenas um grid de cartões de
  funcionalidades** (`ModuleDashboardPage.tsx:61-129`) — sem conteúdo de negócio.

O contrato declarado em `docs/PORTAL-ARCHITECTURE-RULES.md` §10
("rotas geradas dinamicamente a partir de `PORTAL_MODULES` +
`MODULE_PAGE_MAP` + `MODULE_PERMISSION_MAP`") **está describes apenas metade do
caminho**. E o §1 ("`ModuleRegistry` é fonte única de verdade para páginas")
está em conflito com o código: o conteúdo real vem de ~33 `<Route>` explícitos
escritos à mão em `App.tsx`.

Regras de destino derivadas do mapa:

1. **Nenhum `pages/dashboard/X` vira sistema sem antes resolver o §3.** Enquanto

   antes de qualquer realocação.

6. Os 7 órfãos de `financeiro/` devem ser primeiro **classificados** entre

7. `pages/dashboard/` deve continuar existindo apenas como camada de
